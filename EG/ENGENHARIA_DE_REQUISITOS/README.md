#  Engenharia de Requisitos - Resumo e Conceitos

Este material aborda os conceitos fundamentais de **Engenharia de Requisitos**, etapa essencial no desenvolvimento de software que define o que o sistema deve fazer e as condições sob as quais deve operar.

---

## **O que é Engenharia de Requisitos?**

Engenharia de Requisitos é o processo de identificar, analisar, documentar, validar e gerenciar as necessidades e restrições de um sistema de software.

Um dos fatores determinantes para o sucesso ou fracasso de um projeto é a qualidade dos requisitos levantados e especificados.

---

## **Tipos de Requisitos**

### **Funcionais**
- Descrevem os serviços, comportamentos e funções que o sistema deve fornecer.
- **Exemplo:** "O sistema deve permitir o cadastro de novos usuários."

### **Não Funcionais**
- Definem restrições ou condições sobre como o sistema deve funcionar.
- Podem abranger:
  - Desempenho.
  - Usabilidade.
  - Segurança.
  - Portabilidade.
- **Exemplo:** "O sistema deve estar disponível 24 horas por dia."

### **Requisitos de Domínio (Regras de Negócio)**
- São específicos do contexto ou área de atuação do sistema.
- Impõem restrições ou cálculos baseados no negócio.
- **Exemplo:** "Um aluno só pode se matricular em uma disciplina se tiver cumprido os pré-requisitos."

---

## **Etapas do Processo de Engenharia de Requisitos**

1. **Levantamento**
   - Descoberta inicial dos requisitos.
   - Técnicas: entrevistas, questionários, observação, protótipos.

2. **Análise e Negociação**
   - Refinamento e validação dos requisitos.
   - Resolução de conflitos entre requisitos de diferentes stakeholders.

3. **Documentação**
   - Registro formal dos requisitos levantados.
   - Pode incluir o Documento de Visão, Especificações de Casos de Uso, etc.

4. **Validação e Verificação**
   - Garante que os requisitos sejam completos, corretos e compreendidos por todos.
   - Validação: o sistema atende às necessidades dos usuários?
   - Verificação: os requisitos estão claros e consistentes?

5. **Gerência de Requisitos**
   - Controle de mudanças nos requisitos ao longo do projeto.
   - Rastreabilidade e organização.

---

##  **Importância da Engenharia de Requisitos**
- Reduz retrabalho.  
- Diminui conflitos e mal-entendidos.  
- Aumenta a satisfação dos usuários finais.  
- Melhora a estimativa de tempo e custo.  
- Fornece base sólida para o design e a implementação.  

---

## **Técnicas de Levantamento de Requisitos**
- Entrevistas.
- Observação de campo.
- Questionários.
- Cenários de uso.
- Prototipagem.
- Análise de documentos existentes.

---

## **Exemplo de Requisito Funcional**
> RF.01 - O sistema deve permitir o agendamento de consultas por operadores autorizados.
