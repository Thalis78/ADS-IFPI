#  Engenharia de Software II - Resumo e Material de Estudo

Este repositório contém o resumo e os principais conceitos abordados nas aulas e slides de **Engenharia de Software**, incluindo requisitos, modelagem UML, diagramas e conceitos fundamentais para análise e desenvolvimento de sistemas.

---

##  **Conteúdo Resumido**

###  Engenharia de Software
- Definição: Disciplina que trata do desenvolvimento sistemático, disciplinado e quantificável de software.
- Software = Programa + Estrutura de Dados + Documentação.
- Problemas comuns: custos altos, atrasos, baixa qualidade e manutenção complexa.

###  Manutenção e Qualidade
- **Manutenção:** Correção, evolução e refatoração de software (pode representar até 90% dos custos).
- **Qualidade (ISO 25010):**
  - Funcionalidade
  - Usabilidade
  - Confiabilidade
  - Desempenho
  - Portabilidade
  - Manutenabilidade
  - Segurança
  - Compatibilidade

---

##  Engenharia de Requisitos
- **Tipos de Requisitos:**
  - Funcionais: O que o sistema deve fazer.
  - Não Funcionais: Restrições (ex.: desempenho, segurança).
  - De Domínio: Regras específicas do negócio.
- **Etapas do Processo:**
  1. Levantamento (entrevistas, observação, protótipos).
  2. Análise e negociação.
  3. Documentação.
  4. Validação e verificação.
  5. Gerência de requisitos (controle de mudanças).

---

##  Documento de Visão
Exemplo de aplicação: Sistema de Agendamento de Consultas (SAC).
- Define: escopo, stakeholders, ambiente, funcionalidades.
- Requisitos Funcionais identificados (Cadastro, Agendamento, Relatórios, etc).

---

##  Casos de Uso
- Descrição das funcionalidades do sistema do ponto de vista do usuário.
- **Componentes:**
  - Atores
  - Casos de Uso (ex.: "Sacar", "Consultar Saldo")
  - Relacionamentos: Associação, Inclusão (`<<include>>`), Extensão (`<<extend>>`), Generalização.

---

##  Diagramas UML
- **Diagrama de Casos de Uso:** Interações e funcionalidades.
- **Diagrama de Classes:** Estrutura do sistema (atributos, métodos, relações).
- **Diagrama de Sequência:** Comunicação entre objetos.
- **Diagrama de Estados:** Mudanças de estado de um objeto.
- **Diagrama de Domínio:** Representa conceitos e relações do mundo real do problema.
